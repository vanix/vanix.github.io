💡 APCS 中級解題重點

這篇是 APCS 中級實作題「字串解碼」的解題教學。**解碼 = 把編碼過程倒著走**：外層迴圈從最後一筆編碼表反著跑、內層迴圈也從最後一個字反著跑，而且字元要接回「原本被抽出來的那一端」（0 接回左邊、1 接回右邊），最後再用一次左右對調把第一步的影響抵消。

## 字串解碼這題在考什麼？

小虎設計了一個編碼方式，把一個字串變成「樣子完全不一樣、但資訊還在」的新字串，並把這套規則寫成 m 筆 0/1 編碼表。你要做的是**反向操作**：拿到編碼後的訊息，參考編碼表把原始字串還原出來。

題目給你的東西只有四樣：

| 輸入 | 意義 |
| --- | --- |
| `m` | 編碼表有幾筆（最多 100 筆） |
| `n` | 字串長度，每筆編碼表與訊息都是 n 個字元（最多 100） |
| `e₀ … e(m-1)` | m 筆 0/1 字串，每筆長度都是 n |
| 最後一行 | 小虎收到的「已編碼」訊息，n 個大寫英文字母 |

輸出只有一行：**編碼前的原始字串**。

這題不考高階演算法，考的是**字串操作 + 巢狀迴圈 + 「可逆運算」的觀念**。所謂可逆運算，就是編碼做了什麼，解碼就把它反著做回去。

> **先備能力**：會寫巢狀迴圈、會用字串索引取值（`s[0]`、`s[-1]`）、知道 Python 字串是不可變的（要用 `+` 組字串而不是 `append`）就可以來挑戰。

## 編碼規則：小虎到底做了什麼？

先把編碼規則講清楚，後面的解碼才會順。題目定義一個轉換操作 `t = f(s, e)`，分兩個步驟。

![題目描述與轉換操作的兩大步驟](/assets/images/blog/apcs-i400-string-decode/apcs-i400-problem-rules.png){: .normal}
_題目原文的問題描述，小虎定義的轉換操作 t = f(s, e) 包含「對調」與「抽字」兩大步驟。_

### 步驟一：1 的個數是奇數 → 左半邊跟右半邊交換

先看 `e` 裡面有幾個 `1`：

- **奇數個**：把 `s` 平分成兩半，前半段與後半段交換。
- **偶數個**：`s` 完全不動。

「平分」有個麻煩：`s` 的長度可能是奇數。題目的規定是——**長度是奇數時，正中間那個字元不動**，只交換左右兩邊。

![e 的 1 有 3 個是奇數，BCAAD 左右兩半交換後變成 ADABC](/assets/images/blog/apcs-i400-string-decode/apcs-i400-swap-halves.png){: .normal}
_e = 10110 有 3 個 1（奇數），BCAAD 長度為 5，中間的 A 不動，左右兩半交換後得到 ADABC。_

以 `BCAAD`（5 個字）為例：

```text
BCAAD → 左半「AD」+ 中間「A」+ 右半「BC」→ ADABC
```

長度是偶數時就沒有中間字，例如 `ABCDEF`（6 個字）→ `DEFABC`。

### 步驟二：依 e[i] 從左端或右端抽一個字

接著從 `i = 0` 走到 `n - 1`，每一輪看 `e[i]`：

- `e[i] = 0`：取出 `s` 的**第一個**字元當作 `t[i]`，並把 `s` 的第一個字元刪掉。
- `e[i] = 1`：取出 `s` 的**最後一個**字元當作 `t[i]`，並把 `s` 的最後一個字元刪掉。

用題目自己給的例子 `s = BCAAD`、`e = 10110` 走一次：

| i | 0 | 1 | 2 | 3 | 4 |
| --- | --- | --- | --- | --- | --- |
| e[i] | 1 | 0 | 1 | 1 | 0 |
| 剩下的 s | ADAB | DAB | DA | D | （空） |
| 累積的 t | C | CA | CAB | CABA | **CABAD** |

所以 `f(BCAAD, 10110) = CABAD`，這就是題目範例一的原始素材。

## 為什麼要「反向解碼」？四個關鍵觀念

編碼是「從左往右抽、從外往內收」，解碼就得**完全反著來**。有四個地方一定要倒過來：

### 觀念一：外層迴圈要反著跑（用哪一筆編碼表）

編碼時是 `s₀ --e₀--> s₁ --e₁--> s₂ … --e(m-1)--> sₘ`，收到的是最後的 `sₘ`。

解碼要從 `sₘ` 退回 `s₀`，所以編碼表要**先後後先**：先用 `e(m-1)` 還原，再用 `e(m-2)`，最後才用 `e₀`。

> 這就是為什麼第 2 子題組（m 不限）會讓很多人卡住：**m = 1 的時候根本看不出差別，一換成 m = 3 就整串錯掉**。

![三層編碼要反推三次，依序套用 e2 → e1 → e0](/assets/images/blog/apcs-i400-string-decode/apcs-i400-three-layers.png){: .normal}
_範例二有三層編碼，解碼時要依序套用 e2 → e1 → e0，也就是從最後一筆編碼表開始還原。_

### 觀念二：內層迴圈也要反著跑（用第幾個字元）

編碼時 `i` 從 0 走到 `n-1`，`t[0]` 是**第一個**被抽走的字。所以解碼時必須從 `i = n-1` 往回走，才能把字元一個一個接回原本的位置。

**如果正著跑會發生什麼？** `t[0]` 明明是從最左端（或最右端）抽的第一個字，你卻最後才處理它，接回去的位置就整個錯位——而且這題輸出的是「原始字串」，位置錯了就是 WA，沒有模糊地帶。

### 觀念三：字元要接回「原本被抽出來的那一端」

- `e[i] = 0`：編碼時是從**最左邊**抽走，所以解碼要**接回左邊**（放在字串前面）。
- `e[i] = 1`：編碼時是從**最右邊**抽走，所以解碼要**接回右邊**（放在字串後面）。

### 觀念四：左右對調是自己的反轉

把字串左半右半對調一次，再對調一次，就會回到原樣（數學上叫「自身的反函數」）。

所以解碼的順序是：**先把步驟二反向還原完 → 再把左右對調還原回去**。順序不能顛倒，因為編碼時是先對調、再抽字。

## 範例一走讀：CABAD 怎麼還原成 BCAAD？

輸入：

```text
1 5
10110
CABAD
```

**第一步：內層迴圈反著跑（j 從 4 到 0）**

| j | e[j] | 動作 | 目前的 s |
| --- | --- | --- | --- |
| 4 | 0 | 接回左邊：`'D' + s` | D |
| 3 | 1 | 接回右邊：`s + 'A'` | DA |
| 2 | 1 | 接回右邊：`s + 'B'` | DAB |
| 1 | 0 | 接回左邊：`'A' + s` | ADAB |
| 0 | 1 | 接回右邊：`s + 'C'` | **ADABC** |

**第二步：對調還原**

`e = 10110` 有 3 個 `1`，是奇數 → 需要對調。`ADABC` 長度 5，中間的 `A` 不動：

```text
AD + A + BC  →  BC + A + AD  →  BCAAD ✅
```

輸出 `BCAAD`，跟題目答案一模一樣。

## 範例二走讀：RETYWQ 怎麼還原成 QWERTY？

輸入：

```text
3 6
111110
101101
000000
RETYWQ
```

這題是 m = 3，要反推三次。每一輪的規則是「**先反向抽字，再看要不要對調**」：

| 輪次 | 編碼表 | 1 的個數 | 要對調嗎？ | 反向抽字後 | 對調後（= 這一輪的答案） |
| --- | --- | --- | --- | --- | --- |
| 1：e₂ | `000000` | 0 個（偶數） | 不用 | RETYWQ | **RETYWQ** |
| 2：e₁ | `101101` | 4 個（偶數） | 不用 | EWQYTR | **EWQYTR** |
| 3：e₀ | `111110` | 5 個（奇數） | 要 | RTYQWE | **QWERTY** |

第三輪的詳細過程：

1. 反向抽字（j 從 5 到 0，`e₀ = 111110`）→ 得到 `RTYQWE`
2. `111110` 有 5 個 `1`（奇數）→ 左右對調：`RTY` + `QWE` → `QWE` + `RTY` = `QWERTY` ✅

答案是 `QWERTY`，跟題目答案一樣。**建議你自己在紙上推一遍範例二**，推通了再去寫程式，會省下很多除錯時間。

## 完整程式碼（Python）

```python
m, n = map(int, input().split())

e = []
for _ in range(m):
    e.append(input().strip())

t = input().strip()          # 小虎收到的編碼後訊息

for i in range(m - 1, -1, -1):        # 外層：編碼表反著用
    s = ""
    for j in range(n - 1, -1, -1):    # 內層：字元索引也反著用
        if e[i][j] == '1':
            s = s + t[j]              # 原本從最右邊抽 → 接回右邊
        else:
            s = t[j] + s              # 原本從最左邊抽 → 接回左邊

    if e[i].count('1') % 2 == 1:      # 1 的個數是奇數 → 把對調還原
        k = n // 2
        if n % 2 == 0:                # 偶數長度：直接對切
            s = s[k:] + s[:k]
        else:                         # 奇數長度：中間字元留在原位
            s = s[k + 1:] + s[k] + s[:k]

    t = s                             # 這一輪的結果，就是下一輪的輸入

print(s)
```

![先把輸入讀進來：m、n、編碼表與收到的訊息](/assets/images/blog/apcs-i400-string-decode/apcs-i400-read-input.png){: .normal}
_輸入只有四種東西：m、n、m 筆 0/1 編碼表，以及最後一行收到的訊息。_

### 程式逐段說明

**讀取輸入**

```python
m, n = map(int, input().split())
e = []
for _ in range(m):
    e.append(input().strip())
t = input().strip()
```

`e` 是「編碼表清單」，`e[0]` 就是 `e₀`，`e[m-1]` 就是最後一筆 `e(m-1)`。`t` 是收到的訊息，也就是 `sₘ`。

（也可以用串列推導式一行寫完：`e = [input().strip() for _ in range(m)]`，效果完全相同。）

**外層迴圈：`for i in range(m - 1, -1, -1)`**

`range(m-1, -1, -1)` 會生出 `m-1, m-2, …, 0`，剛好是編碼表的**反序**。這是整題最重要的一行。

**內層迴圈：`for j in range(n - 1, -1, -1)`**

同理，字元索引也反序走。注意 `t[j]` 取的是**當前這一輪的字串**，所以每輪結束後要把 `s` 寫回 `t`（`t = s`）。

**接回左邊 / 右邊**

Python 字串不可變，所以只能用 `+`：

```python
s = t[j] + s      # 接回左邊（e[i][j] == '0'）
s = s + t[j]      # 接回右邊（e[i][j] == '1'）
```

**對調還原**

`k = n // 2` 是左半邊的長度：

- 偶數長度：`s[k:] + s[:k]`
- 奇數長度：中間字元 `s[k]` 要留在兩邊中間 → `s[k+1:] + s[k] + s[:k]`

![外層反著跑，內層也反著跑的反向解碼寫法](/assets/images/blog/apcs-i400-string-decode/apcs-i400-reverse-decode.png){: .normal}
_雙層迴圈都反著跑：i 從 m-1 到 0，j 從 n-1 到 0，0 接回左邊、1 接回右邊。_

![最後把「對調」還原：奇數個 1 才處理，長度奇數時中間字元留在原位](/assets/images/blog/apcs-i400-string-decode/apcs-i400-undo-swap.png){: .normal}
_內層還原完之後，最後才處理左右對調；長度是奇數時，中間字元要留在原位。_

## 常見錯誤與除錯

**❌ 內層迴圈正著跑**

`for j in range(n)` 一定是錯的。編碼時 `t[0]` 是最早被抽走的字，解碼就要最後才接回去。

**❌ 0 和 1 接反邊**

記法：**0 接左、1 接右**。編碼時 0 從左抽、1 從右抽，解碼就原路送回。寫錯的話結果會整個反過來。

**❌ 每輪結束忘了 `t = s`**

這是連我自己在錄影時都踩到的坑（影片大約 19 分半鐘處）：第一輪跑完 `t` 還停在「最初收到的訊息」，第二輪就用舊資料繼續算，結果字串越接越長、還會用到已經不該用的 `t`。**每一輪結束一定要把結果寫回 `t`。**

**❌ 對調的時機放錯**

對調是「步驟一」的逆操作，所以必須在**內層抽字還原之後**做，不是之前。

**❌ 奇數長度時中間字元被換走**

`s[k+1:] + s[k] + s[:k]` 與 `s[k:] + s[:k]` 只差在奇數長度，寫錯就會讓中間那個字元跑到別的位置。

**❌ `count("1")` 算錯對象**

要算的是「**當前這一筆**編碼表」裡的 1 個數，也就是 `e[i].count("1")`，不是全部編碼表加起來。

## 常見問題（FAQ）

### Q1：為什麼解碼要從最後一筆編碼表開始？

因為編碼是「疊蛋糕」：先用 `e₀` 蓋一層，再用 `e₁` 蓋一層……你收到的訊息是最上層。要拆蛋糕，只能從最上面那層先拆。也就是 `e(m-1)` → `e(m-2)` → … → `e₀`。

### Q2：左右對調做了兩次，不就等於沒做？

對，**對調是自己的反轉**，所以解碼時對調一次就會回到編碼前的樣子。關鍵是「做對順序」：編碼是「先對調、再抽字」，解碼就要「先反向抽字、再對調」。

### Q3：字串長度是奇數怎麼辦？

中間那個字元不參與交換，留在原位。以 `BCAAD` 為例，`k = 2`，`s[:2] = "AD"` 是左半、`s[2] = "A"` 是中間、`s[3:] = "BC"` 是右半，對調後就是 `BC` + `A` + `AD` = `BCAAD`。

### Q4：這題的時間複雜度是多少？

外層跑 m 輪，內層每輪跑 n 次，對調也是 O(n)，所以時間複雜度是 **O(m × n)**，m、n 都只有 100，執行時間 1 秒內綽綽有餘。空間複雜度 O(m × n)（存編碼表）。

### Q5：可以不用字串 `+` 組合，改用串列嗎？

可以，但**本題建議直接用字串 `+`**，因為 n ≤ 100，效能完全夠，而且程式碼跟題目邏輯完全對得上，比較好理解。用 `list` + `append` + `join` 也可以，只是要多寫幾行轉換。

## 小結

「字串解碼」是 APCS 中級用來練**字串操作與巢狀迴圈**的好題，題目本身不難，但有四個關鍵觀念一定要記牢：

1. **編碼表反著用**：`range(m-1, -1, -1)`，先後後先。
2. **字元索引反著跑**：`range(n-1, -1, -1)`，先抽的最後接回。
3. **0 接左、1 接右**，字元要送回原本被抽出來的那一端。
4. **對調還原放最後**，而且只有當輪 1 的個數是奇數時才要做。

把這四件事寫對，程式就只有十幾行；寫錯的話，範例一可能還會過，範例二一定爆。建議你先照著邏輯手推範例二，推通了再來寫程式，會比自己苦思 Bug 快很多。
