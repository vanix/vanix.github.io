## 這題在考什麼？

「蒐集寶石」（ZeroJudge o712）是 APCS 終極範例題中的第二題。題目給定一張 `M × N` 的地圖，每一格記錄寶石數量，若數字是 `-1` 就代表牆壁。

機器人一開始位於 `(r, c)`，初始方向**朝右（東方）**，並且遵循一套固定規則不斷移動、蒐集寶石，直到滿足某個終止條件才停止。最後要輸出**機器人總共撿了幾顆寶石**。

這題考的不是演算法（像 DFS/BFS 最短路徑那種），而是**模擬（Simulation）**：把題目每一個步驟用程式一行一行照著做。只要規則讀懂、順序寫對就能解出來。

## 地圖、初始狀態與基本定義

| 項目 | 說明 |
| --- | --- |
| 地圖 | `M × N`，每格是整數。`-1` 代表**牆壁**，其他數字代表**該格目前的寶石數量**。 |
| 機器人初始位置 | `(r, c)`（由輸入給定） |
| 初始方向 | **向右（東方）** |
| 分數 `score` | 初始值 `0`，每次走到某個格子，都會加上「當前格的寶石數量」 |
| 寶石數量統計 | 題目最後要輸出「機器人總共撿了幾顆寶石」。每次走到某個格子都會撿起一顆寶石，準備另一個變數儲存撿起的寶石數量 |
| 場地邊界 | 假設場地周圍是牆壁。若面向的格子**超出地圖邊界**，也視為「牆壁」或「不可前進」。 |

## 機器人行走規則（逐步解析）

機器人每一個循環大致會照以下步驟執行：

### 規則 1：若當前格子的寶石數量為 0，則機器人程式終止
走到某個格子時，**第一件事**就是檢查這個格子現在的寶石數量。如果已經是 `0`，表示這個格子已經被撿過（或本來就沒寶石），機器人就要**立刻停止**。

這是本題最關鍵的終止條件，影片範例最後就走回 `(0,3)` 時，該格寶石數量變成 `0`，於是機器人停止。

### 規則 2：加分數、撿起一顆寶石
若當前格子的寶石數量**不為 0**，就：
- 將 `score` 加上**當前格的寶石數量**
- **撿起一顆寶石**，寶石數量+1
- 並且該格的寶石數量減 1

換句話說：每次經過這個格子，只要還有寶石就能撿。撿走之後，格子上的數值就會變少，下一次如果再走回來就要再用規則 1 檢查。

### 規則 3：若 `score` 是 `k` 的倍數，則向右轉 90 度
在規則 2 執行完之後，檢查 `score % k == 0`。如果是，就**向右轉 90 度**。

注意：這裡說的是「向右轉 90 度」，不是「往右走」。方向改變了，但**不代表立刻移動**，還要接著規則 4 處理。

### 規則 4：調整方向直到能前進，再回到第 1 步
現在機器人要往「目前面向」的方向走。如果**面向的格子是牆壁（-1）或是超出邊界**，就**繼續向右轉 90 度**，重複這個動作，直到面向的格子**不是牆壁且沒有超出邊界**為止。調整好方向之後，**往前走一步**，再回到**規則 1** 繼續執行。

這個「持續向右轉」的動作很重要。影片中範例就有好幾次需要**轉 2 次**才找到可以走的方向。

## 影片範例走讀（重點觀察）

讓我們跟著影片的邏輯來理解整個流程：

> 範例中給定初始位置 `(2,1)`，`k = 2`，一開始面向右邊。

整個過程重點如下：

1. **向右走兩步**：經過幾個格子後，分數累積到 `3 + 2 + 3 = 8`。由於 `8` 是 `k=2` 的倍數，所以**向右轉 90 度**。
2. **轉向後往下走**：接著往下走一步，分數變成 `11`此時發現**面向的方向是邊界**，**向右轉 90 度**，轉向後發現前方是牆壁，所以又**向右轉 90 度**，總共轉了 **2 次** 才找到可以走的方向。
3. **再往前走**：走到 `(2,3)`，因為這個位置**之前已經拿走過一顆寶石**，現在該格的寶石數量變成 `2`，所以分數變成 `13`。接著往上走兩步到 `(0,3)`，分數變成 `16`，`16 % 2 == 0`，於是向右轉 90 度。
4. **調整方向並結束**：往前走到 `(0,4)` 後，需要**向右轉兩次 90 度**才找到路。回到 `(0,3)` 時，該格寶石數量已經是 `0`，因此機器人**停止**。整個過程中總共撿了 **8 顆寶石**。

從這個範例可以歸納出幾個重點：

- **「撿起一顆寶石」** 指的是把該格的寶石**拿走**。地圖上的數值會減 1，變成 0 之後再走回來就會觸發規則 1 終止。
- **轉向發生在「加完分數」之後**（規則 2 執行完才檢查規則 3）。
- **轉向判斷是「分數是否為 k 的倍數」**，不是看走了幾步或經過幾個格子。
- **規則 4 是「邊界或牆壁才轉」**。如果面前可以走，就**不用轉向**，直接往前走一步。
- **「持續向右轉」**：有時要轉 1 次、有時要轉 2 次，有時還要轉 3 次也可能（四個方向全部被擋住的極端情況很少見，但規則寫得很清楚要**持續向右轉直到能走為止**）。

## 輸入格式

第一行：`M N k`（或依題目給定的順序，實際要看題目說明；以下以 ZeroJudge 常用格式說明）

接下來 `M` 行（或 `M` 列的資料）：每行有 `N` 個整數，代表地圖每一格的數值。`-1` 表示牆壁。

再接下來一行：`r c`，代表機器人初始位置。

（建議直接用 ZeroJudge 上的題目頁面確認當次輸入格式，寫程式時用 `input()` 讀取即可。）

## 解題思路：用模擬 + 方向陣列

要解這題最直覺的方式就是**照規則模擬**。建議用以下結構來實作：

### 1. 準備資料結構

```python
# 讀入地圖
grid = [list of ints for each row]

# 讀入初始位置
r, c = start_r, start_c

# 讀入 k
k = ...

# 分數與方向
score = 0
# 方向：初始朝右（東方）
# 常用順序：右、下、左、上（因為規則是「向右轉 90 度」）
dr = [0, 1, 0, -1]
dc = [1, 0, -1, 0]
dir_idx = 0  # 0 = 向右

# 統計撿到幾顆寶石
count_gems = 0
```

選用 `dr/dc` 的順序要對應「向右轉 90 度」。如果現在方向是 `dir_idx = 0`（向右），**向右轉 90 度** 就會變成「向下」。所以陣列要設成 `[右, 下, 左, 上]` 才好用 `(dir_idx + 1) % 4` 來轉向。

### 2. 主迴圈（模擬流程）

我們需要不斷重複，直到規則 1 觸發終止：(以下為AI範例程式，跟宅爸實際寫的程式會有些許不同)

```python
while True:
    # 規則 1：檢查當前格寶石數量
    if grid[r][c] == 0:
        break  # 終止程式
    # 規則 2：加分數、撿起一顆寶石
    val = grid[r][c]
    score += val
    grid[r][c] -= 1  # 撿走一顆寶石（減 1）
    count_gems += 1
    
    # 規則 3：若 score 是 k 的倍數，向右轉 90 度
    if k != 0 and score % k == 0:
        dir_idx = (dir_idx + 1) % 4
    
    # 規則 4：若面前是牆壁或超出邊界，持續向右轉直到能前進
    # 檢查目前方向能不能走
    while True:
        nr, nc = r + dr[dir_idx], c + dc[dir_idx]
        # 檢查是否牆壁或超出邊界
        if nr < 0 or nr >= M or nc < 0 or nc >= N or grid[nr][nc] == -1:
            # 不能走，向右轉 90 度
            dir_idx = (dir_idx + 1) % 4
            continue
        else:
            # 可以走，往前走一步
            r, c = nr, nc
            break
    
    # 回到規則 1
```

**幾個實作細節要注意：**

- **檢查順序很關鍵**：每次迴圈都要先用規則 1 檢查「現在站著的格子」。所以如果走到一個格子、撿完變成 0，下一次迴圈一開始就會偵測到 `grid[r][c] == 0` 然後 `break`。
- **修改地圖**：一定要把 `grid[r][c] -= 1` 寫進去。否則下一次走回來就不會知道這個格子已經空了，程式就會永遠不會終止。
- **轉向只在規則 3**：規則 4 裡的「向右轉」是**為了找路**（避開牆壁或邊界），跟分數是否為 k 的倍數無關。這兩種轉向的原因不同，要分清楚。
- **「持續向右轉」**：規則 4 用 `while True` 配合 `continue` 來做。每次轉向後都要**重新檢查**新方向的前方是否可走。理論上最多轉 4 次就一定會找到方向（除非整個機器人四周都被牆壁包圍，但題目假設場地周圍是牆壁，機器人一開始也給了位置，實際測資應該不會卡在完全被包圍的情況）。
- **k 的倍數判斷**：題目寫「若 `score` 是 `k` 的倍數」，在程式中要用 `score % k == 0`。要小心 `k` 可能是 `1` 的情況（每次加完分數都會轉向）。
- **走出邊界要當牆壁**：在檢查前方時，先判斷 `nr,nc` 是否在 `0 <= nr < M` 且 `0 <= nc < N` 之外，只要超出就當成不可走。

## 用影片邏輯驗證（簡單對照）

影片裡的重點「走到 `(0,3)` 寶石數變 0 後停止」剛好對應我們的流程：機器人走到 `(0,3)` 時格子還有寶石 → 執行規則 2 把它減成 0、加分數、累計撿寶石數 → 規則 3、4 處理轉向與前進 → **下一次迴圈一開始**就會因為 `grid[0][3] == 0` 而 `break`，正確地在那個位置結束。

這個「走到格子 → 處理規則 → 下一輪才檢查終止」的順序千萬別搞反。**終止是「走到格子內寶石數量為 0」的時候才發生**，不是走過之後就立刻結束。

## 完整 Python 程式碼（參考實作）

以下為AI範例程式，他擅自寫成了函數並加上try except，宅爸影片中的程式碼會簡短一些

```python
import sys
sys.setrecursionlimit(10**7)

def main():
    try:
        # 輸入
        M, N, k, r, c = map(int, sys.stdin.readline().split())  # 地圖大小、 k 、初始位置
        grid = []
        for i in range(M):
            row = list(map(int, sys.stdin.readline().split()))  # 每列的寶石數量或 -1
            grid.append(row)
        
        # 方向：右、下、左、上（向右轉 90 度）
        dr = [0, 1, 0, -1]
        dc = [1, 0, -1, 0]
        dir_idx = 0  # 初始朝右
        
        score = 0
        gem_count = 0
        
        while True:
            # 規則 1：若當前格子的寶石數量為 0，則機器人程式終止
            if grid[r][c] == 0:
                break
            
            # 規則 2：加分數，撿起一顆寶石
            val = grid[r][c]
            if val == -1:
                # 理論上不應該走到牆壁，但保險起見
                pass
            else:
                score += val
                grid[r][c] -= 1
                gem_count += 1
            
            # 規則 3：若 score 是 k 的倍數，則向右轉 90 度
            if k != 0 and score % k == 0:
                dir_idx = (dir_idx + 1) % 4
            
            # 規則 4：若面前是牆壁或超出邊界，持續向右轉直到能前進
            while True:
                nr = r + dr[dir_idx]
                nc = c + dc[dir_idx]
                # 檢查是否超出邊界或是牆壁
                if nr < 0 or nr >= M or nc < 0 or nc >= N or grid[nr][nc] == -1:
                    dir_idx = (dir_idx + 1) % 4
                    continue
                else:
                    # 可以前進
                    r, c = nr, nc
                    break
            
            # 回到規則 1
        
        print(gem_count)
        
    except EOFError:
        print(0)
    except:
        print(0)

# 執行主程式
if __name__ == "__main__":
    main()
```


## 常見錯誤與除錯技巧

| 錯誤 | 原因 | 解法 |
| --- | --- | --- |
| **無限迴圈** | 沒有把格子上的寶石數減 1，導致永遠不會遇到寶石數為 0 | 一定要執行 `grid[r][c] -= 1`（規則 2） |
| **提早或延後終止** | 把規則 1 放錯位置，或在撿完寶石就直接結束 | 規則 1 要放在**迴圈一開始**，每次「走到」新格子時就先檢查 |
| **轉向時機錯誤** | 在「找路」（規則 4）時誤用分數判斷，或在規則 2 前就轉向 | 規則 3 只發生在**規則 2 執行完**之後。規則 4 的轉向只為了避開牆壁 |
| **方向陣列順序錯** | 用了 `右、左、下、上` 之類的順序，導致「向右轉 90 度」算錯方向 | 用 `右、下、左、上`，再用 `(dir_idx + 1) % 4` |
| **沒考慮超出邊界** | 只檢查 `grid[nr][nc] == -1`，卻沒檢查 `nr,nc` 是否超出陣列範圍 | 先檢查邊界：`nr < 0 or nr >= M or nc < 0 or nc >= N` 就當成牆壁 |
| **誤把牆壁當成可走** | 地圖上 `-1` 是牆壁，絕對不能走進去 | 在規則 4 的檢查裡也要排除 `grid[nr][nc] == -1` |

## 解題步驟建議

1. **先讀懂規則**：把上面 4 條規則用自己的話寫一遍，特別搞清楚「什麼時候轉向」「什麼時候終止」。
2. **畫個簡單範例**：用紙筆把影片那個小例子走一遍，親手模擬每一步的 `score`、方向、地圖狀態（寶石是否被拿走）。
3. **先用假資料測試**：不用急著寫完整輸入，先用範例的地圖跟初始位置硬模擬，確認邏輯對了再寫程式。
4. **實作模擬迴圈**：照著上面的結構寫，先別想太多最佳化，先追求「照規則走對」。
5. **小心除錯**：建議印出 `r,c,dir_idx,score,gem_count` 每一輪的狀態（測試時用），找出哪一輪跟你手算的不一樣就能很快抓到 bug。

## 總結

o712「蒐集寶石」的本質是**狀態機模擬**：狀態包含「目前位置 `(r,c)`」、「目前方向 `dir_idx`」、「目前分數 `score`」、「地圖上每格剩餘寶石數量」。

每一次迴圈都固定做四件事：**檢查終止（規則 1）→ 撿寶石加分（規則 2）→ 可能轉向（規則 3）→ 找路並前進（規則 4）**。記住兩種轉向的差別、記住「下一輪才檢查寶石數為 0」這個順序，你就能輕鬆解出這題。

建議先跟著影片的範例用紙筆走兩遍，等腦中有畫面再開始寫程式，會比直接硬寫來得快很多。
